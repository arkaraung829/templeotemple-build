Fork Strategy

Reuse from cuckoo, don't rebuild

  • Razorpay Route split settlement + gateway-agnostic payment_gateway_config
  • Category-wise commission (2–15%) model
  • One category engine for products AND services (category_attribute_schemas)
  • translations table + category images/order — Burmese → Tamil
  • GST / TCS / TDS: gstin+pan, hsn_code+tax_rate, invoicing
  • Seller KYC: GSTIN/PAN + penny-drop bank verification
  • Buyer + Seller + Admin scaffolds · App/Play Store checklists
Build from scratch: temple categories (data), service availability calendars, donations, membership/savings, new-temple-build funds, temple-admin role, deity/festival banners, AI temple finder, reskin + Tamil l10n.

Business Workflows

16 end-to-end processes

Happy path + failure + back-office. Full detail in WORKFLOWS.md.

1 · Product order lifecycle

cart → checkout → pay → paid → notify seller
  accept → pack → packed → delivery → shipped → delivered → payout
  fail: reject/out-of-stock → auto-refund · payment fail → expire 30m, release stock

2 · Service booking lifecycle

pick service → slot → pay → confirmed → provider confirms (slot locked)
  → performed → completed → payout
  fail: no-show → reassign backup OR refund · cancel → per-category rule

3 · Quotation loop (events / sthapathi)

requirement → requested → vendor quote → sent
  → accept → advance pay → booking · (revise = loop) · (reject = closed)

4 · Payment → commission → payout settlement

captured → split: vendor = price − commission(cat%) − gateway
  held until fulfilled → payout pending → settlement run (daily/weekly) → settled
  min payout threshold · GST 18% on commission · TCS/TDS · RBI escrow

5 · Refund / cancellation / dispute

trigger → policy & fee check → issue_refund() (reverse payment + clawback payout + restock)
  dispute: buyer raises → disputed → admin reviews → refund / release
